DRISHTI DRIVE VEHICLE SURVEILLANCE PROJECT
==========================================

Purpose
-------
A multi-page vehicle surveillance application with:
  1. Home/menu dashboard
  2. ANPR live camera and owner-compliance page
  3. Tracking/OCR vehicle route page
  4. Traffic heatmap and live camera page

Tracking vehicle-search flow:
  1. Normalize the entered plate.
  2. Search all cameras/*.csv files.
  3. Select the relevant historical date when no date is supplied.
  4. Sort sightings by timestamp.
  5. Load owner details from menu/owner_details.csv.
  6. Populate start/end camera locations.
  7. Draw the route using Leaflet and optional OSRM road routing.

        |       /traffic/map.html
        |             |
        |             +--> Poll /traffic/api/traffic-data every 5 seconds
        |             +--> Rebuild colored camera heat circles
        |
        +--> Vehicle slots:
                Poll /traffic/api/live-detections every 5 seconds
                CAM1 slot <- cam1_traffic.csv
                CAM2 slot <- cam2_traffic.csv
                CAM3 slot <- cam3_traffic.csv
                CAM4 slot <- cam4_traffic.csv

Traffic video flow:
  Camera feed request
        |
        v
  get_video_files() discovers video*.mp4
        |
        v
  Start camera N at video N
        |
        v
  YOLO processes every frame
        |
        v
  At video end, advance to next available video
        |
        v
  video1 -> video2 -> video3 -> video4 -> video1

Traffic count flow:
  Read each *_traffic.csv
        |
        v
  Keep rows from the current rolling 60-second time window
        |
        v
  Normalize vehicle IDs and count distinct runtime entries per camera
        |
        v
  Apply traffic color:
    0-10 vehicles  -> blue  (#2196f3)
    11-15 vehicles -> orange (#ff9800)
    16+ vehicles   -> red   (#f44336)
        |
        v
  Return camera count, level, coordinates and color
        |
        v
  Leaflet map renders colored traffic circles

KEY ARCHITECTURE NOTES
----------------------

  - menu/app.py is the active integrated entrypoint for all three pages.
  - main.py is an older standalone tracking implementation.
  - Tracking CSV sightings are historical route data.
  - Traffic CSV files are runtime traffic-entry data.
  - YOLO detects objects in video frames.
    Traffic YOLO detections are written as per-camera runtime vehicle IDs.
  - PaddleOCR reads license plates from uploaded images in Tracking/OCR.
  - Owner data is registry data, separate from camera sightings.
  - The frontend map pages are iframe-based Leaflet applications.
  - Traffic counts use a rolling 60-second window based on CSV time values.
    - Traffic backend appends detected vehicle IDs to camN_traffic.csv every 5 seconds per active track.
  - Traffic heatmap and camera plate slots refresh every 5 seconds.
  - Tracking route is drawn only after a plate exists in camera CSV records.
